## 4. 行为变化

### Phase 1 — 唯一配对控制器门禁
- 新增 `server/controller-store.js`：`run/controller.json` 原子写、corrupt 标记、set 替换、isController。
- `POST /siri/pair` 生成随机 deviceId 并写入 controller.json，下发新格式配对 Cookie（`siri_pair=<deviceId>.<HMAC>`，HttpOnly/SameSite=Strict）。
- 只有「WS 认证通过 + Cookie 校验 + deviceId 等于 controller.json」的连接才是 controller；controller 才能收 play.req、触发离线投递、结算 play.ack、用 session.reauth.req。
- 同 iPad 多标签页：最新成功认证的标签页替换旧连接并关闭旧连接（WS close 4001 `controller_replaced`）。
- 普通 WebUI 在线但 controller 离线时，`POST /api/siri/play` 一律返回 **202 queued**。

### Phase 2 — 协议 v2
- `PROTOCOL_VERSION` 升为 2；`auth.ok` 携带 `version/paired/controller`。
- 版本不匹配 → `auth.error {reason:'protocol_mismatch', expected}` + close 1002。
- 客户端把 protocol_mismatch 视为永久失败（不无限重连），写入 `window.__siri.lastError` 并提示刷新 WebUI 更新缓存。
- `window.__siri` 新增 `protocol/paired/controller`，paired/controller 从 auth.ok 读取（不再依赖 document.cookie，修复 HttpOnly Cookie 恒 false 的遗留 bug）。

### Phase 3 — 真实播放 ACK
- ACK 成功判定改为轮询（100ms，最长 2s）：`player.currentSong?.hash === expectedSong.hash && player.playing === true`。
- 不能只查 `playing`（旧歌可能仍在播）；必须 hash 匹配 + 正在播放才 ack ok。
- 超时分类：`navigator.userActivation?.hasBeenActive === false` → `AUTOPLAY_BLOCKED`；其余（含 userActivation 不存在）→ `PLAY_FAILED`。
- `shouldPlayNext` → `PLAY_FAILED`（语义是取 URL 失败/无版权，不是自动播放拦截）。
- 不做 `new Audio()`，不绕过播放器，不改 MoeKoeMusic 的 src/api。

### Phase 4 — ACK 绑定目标连接
- `pending.js`：`submit(query, {targetConnectionId})`、`setTarget(reqId, connectionId)`；`handleAck(ack, connectionId)` 只接受目标连接的 ACK，非目标 ACK 忽略并打 warning。
- 删除 `PENDING_SUCCESS_GRACE_MS` / fallbackAck / 广播回退分支；失败 ACK 立即结算。
- `offline-command.js`：`handleAck(ack, connectionId)` 同样校验目标连接；controller 掉线后离线命令自动重排队。
- `http-api.js`：dispatch 成功后把 pending 绑定到实际接收连接的 connectionId。

### Phase 5 — 网络安全收口
- HTTP token 只允许 `x-siri-token` 头；`?token=` 一律 401（含正确 token）。
- `scripts/firewall.ps1`（新增）：默认只检查；`-Apply` 建 8080/8200 TCP 入站（Private + LocalSubnet）；`-Rollback` 只删本脚本创建且名为 `MoeKoeSiriControl-*` 的规则；不自动删旧规则。
- `scripts/start-all.ps1`：以 `set HOST=127.0.0.1` 启动 6521（KuGou API 仅 loopback，无防火墙规则）。

### Phase 6 — 会话登录熔断
- 状态机：`ready` / `cooldown` / `hard_stopped`。
  - `AUTH_REJECTED` / `RISK_REQUIRED` → `hard_stopped`（永久停，需 reset() 恢复）。
  - `UPSTREAM_UNAVAILABLE` / `TIMEOUT` → 60s cooldown。
- 小时预算：每滚动小时最多 5 次真实上游登录，超出返回 `BUDGET_EXCEEDED` 不碰上游。
- 单飞（并发登录只发一次上游请求）；成功清空预算并回到 ready。
- 新增 `status()`；`/debug/status` 与 `/health` 输出 `configured/state/lastError/cooldownUntil/attemptsRemaining`。

### Phase 7 — 运维诊断
- `scripts/doctor.ps1`（新增）：只读体检——node 版本、.env/token、dist、端口、controller 配对、/health（含 upstream/sessionAuth）、防火墙规则、备份、日志归档、两个仓库 git 状态；硬检查失败退出码非 0。
- `scripts/status.ps1`：扩展输出配对状态、/health 的 controller/upstream/sessionAuth、日志文件大小与时间、相关 node 进程。
- `/health` 扩展：新增 `upstream {url, reachable, status, checkedAt}` 与 `sessionAuth`；index.js 启动时 + 每 60s 探测上游。
- 日志轮转：`start-all.ps1` 启动前把 `run/*.log` 归档到 `run/logs-archive/<时间戳>`，保留最近 10 个归档、文件超过 14 天删除；文件被占用时仅告警不中断。
- `build-web.mjs`：构建前把当前 dist 快照到 `backups/dist.prev`（旧快照保留为 `dist.prev.old`）。

## 6. 风险与注意事项

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 换设备 | `controller.json` 是唯一事实源 | 在新 iPad 上重新访问 `/siri/pair` |
| 局域网访问 | 8080/8200 未开防火墙规则时 iPad 连不上 | `scripts/firewall.ps1 -Apply`（管理员） |
| 熔断 hard_stopped | AUTH_REJECTED/RISK_REQUIRED 后不再尝试 | `reset()` 或重启服务；改密后由运维处理 |
| 旧缓存客户端 | 协议 v2 下旧 SW 缓存会拿到 protocol_mismatch | 强制刷新/重进 WebUI 更新缓存 |
| 日志轮转 | 运行中的日志文件被占用 | 轮转仅告警，不中断启动 |

## 7. iPad 升级步骤

1. 更新代码：`git pull`（或取新代码）；确认 `.env` 不变。
2. `npm test`（201/201）。
3. `npm run build:web` + `npm run verify:web`。
4. `npm run stop:all` → `npm run start:all`（自动归档旧日志、快照旧 dist）。
5. iPad 打开 WebUI：如提示协议不匹配，强制刷新 / 重新进入（清除旧 Service Worker 缓存）。
6. `scripts/doctor.ps1` 确认全部 OK；局域网 iPad 访问还需以管理员运行 `scripts/firewall.ps1 -Apply`。

## 8. 回滚步骤

1. 单阶段回滚：`git revert <该阶段提交>`（禁止 `git reset --hard`），然后 `npm run build:web`、`npm run stop:all` / `start:all`。
2. 前端回滚：把 `backups/dist.prev`（或 `backups/dist.prev.old`）复制回 `MoeKoeMusic/dist` 覆盖，再 `start:all`。
3. 保留约束：不删 `.env`、不删 `run/` 日志与 `backups/` 备份；防火墙规则只在显式 `-Rollback` 且只删本脚本创建的规则。
